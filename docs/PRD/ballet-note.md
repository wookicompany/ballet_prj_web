## 1. 개요

| 항목 | 내용 |
|---|---|
| 목표 | 발레에 쓰는 비용을 캘린더 기반으로 기록하고, 월과 년 단위로 얼마 썼는지 한눈에 본다 |
| 배경 | 이 앱은 캘린더 퍼스트라 사용자가 이미 날짜 기반 입력에 익숙하다. 레슨비, 슈즈, 의상, 공연 티켓처럼 흩어진 지출을 한곳에 모으면 "내가 발레에 얼마를 쓰는지"라는 질문에 답할 수 있다 |
| 진입 | **프로필** (탭바 아님 — 사용률을 검증한 뒤 승격 판단) |
| 원칙 | KST 날짜, 소프트 삭제, 쓰기는 서버 API, 전체 실패(all-or-nothing), 어요체, 사용자 카피에 가운뎃점 없음 |

**탭바에 넣지 않는 이유**: 탭 4개(캘린더, 공연, 브랜드, 프로필)를 유지한다. 티켓북도 공연 탭 안의 아이콘으로 넣었고 같은 판단이다. 사용률이 확인되면 그때 승격을 논의한다.

| 홈 | 월 캘린더 | 날짜 셀에 그날 지출 합계 배지. 상단에 연월 이동과 그 달 총지출 |
| 홈 | 날짜 선택 | 그날 지출 항목 리스트(금액, 태그, 메모)를 아래에 펼침 |
| 홈 | 월 전환 | 좌우 스와이프와 연월 선택 시트 |
| 등록 | 지출 추가 | 날짜, 금액, 태그, 메모 |

| 집계 | 월별 / 년도별 전환 | 총지출과 태그별 합계를 금액순 리스트로 |
| 어드민 | 발레노트 관리 | 목록과 상세 조회 (수정과 삭제 없음) |

## 3. 화면 스펙

### S1. 프로필 진입점

| 구성요소 | 내용 |
|---|---|
| 위치 | 프로필의 "기록 요약" 섹션 아래 |
| 표시 | "발레 비용" 타이틀 + 이번 달 지출 / 올해 지출 두 값 |
| 데이터 없을 때 | 금액 대신 "발레에 쓴 비용을 기록해 보세요" 안내 |
| 액션 | 카드 탭 → 발레노트 홈(S2) |

### S2. 발레노트 홈 (`/ballet-note`)

| 구성요소 | 내용 |
|---|---|
| 형태 | 월 캘린더. **기록 캘린더와 시각적으로 구분한다** — 감정 이미지나 점선 원 없이 **날짜 셀 아래 그날 지출 합계 배지**가 중심 |
| 헤더 | 티켓북과 동일한 2단 구조. 1단 `PageHeader`("발레노트"), 2단 왼쪽 연월 버튼 + 오른쪽 추가 버튼 |
| 그 달 총지출 | 2단 헤더 아래 또는 캘린더 상단에 한 줄로 |
| 날짜 탭 | 그날 지출 항목 리스트를 캘린더 아래에 펼침. 항목 탭 → 수정 시트(S3) |
| 지출 없는 날 탭 | 그 날짜를 기본값으로 추가 시트 열기 |
| 월 전환 | 좌우 스와이프 + 연월 선택 시트 (티켓북과 동일 규격) |
| 집계 이동 | 상단에서 월↔년 집계(S4)로 전환 |

### S3. 지출 추가·수정 시트

| 항목 | 필수 | 내용 |
|---|---|---|
| 날짜 | 필수 | 기본값은 오늘(KST). 홈에서 날짜를 선택한 상태면 그 날짜 |
| 금액 | 필수 | 숫자 입력(원). 천 단위 구분 표시, 0 이하 불가 |
| 태그 | 선택 | **사용자 생성 태그 1개**. 직접 입력하며 내 기존 태그를 자동완성으로 제안 |
| 메모 | 선택 | 자유 텍스트 |
| 저장 | | 서버 API로 생성 또는 수정. 실패 시 전체 실패 + 토스트 |
| 삭제 | | 수정 시트에서만. 확인 다이얼로그 후 소프트 삭제 |

### S4. 기간 집계 (`/ballet-note/summary`)

## 4. 데이터 모델

### `ballet_expenses`

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | uuid PK | `gen_random_uuid()` |
| `user_id` | uuid NOT NULL | 소유자 |
| `spent_on` | date NOT NULL | 지출 날짜(KST 기준으로 만든 문자열) |
| `amount` | integer NOT NULL | 금액(원). `CHECK (amount > 0)` |
| `tag` | text | 사용자 태그 1개 (nullable) |
| `memo` | text | 메모 (nullable) |
| `created_at` / `updated_at` | timestamptz NOT NULL | `now()` |
| `deleted_at` | timestamptz | 소프트 삭제 |

**인덱스**: `(user_id, spent_on)` — 월 조회와 집계가 전부 이 조합을 탄다. `(user_id, tag)` — 태그 자동완성과 태그별 집계용.

**RLS**: 본인 행만 select. **`deleted_at`은 RLS가 검사하지 않으므로 앱 코드가 반드시 직접 `is("deleted_at", null)`을 건다** (티켓북에서 확인된 규칙).

**집계**: 월과 년은 `spent_on` 범위 조회 후 클라이언트에서 합산하거나, 건수가 커지면 RPC로 GROUP BY. 태그 자동완성은 본인 행의 `DISTINCT tag`.

`lib/database.types.ts`는 **수동 갱신**해야 빌드가 통과한다.

## 5. 구현 규칙 (티켓북에서 확인된 것)

문서로 남겨두지 않으면 반복해서 밟는 함정들이다.

| 항목 | 규칙 |
|---|---|
| 쓰기 경로 | INSERT/UPDATE/DELETE는 서버 API Route에서 service role로만. 클라이언트는 조회만 |
| 소유권 검사 | PATCH/DELETE 전에 대상 행을 먼저 조회 — 없으면 404, 타인 소유면 403 |
| RPC를 쓴다면 | 라우트가 `getUserFromRequest`로 인증한 뒤 `supabaseAdmin`으로 호출하므로 **RPC 안에서 `auth.uid()`는 항상 NULL이다.** `p_user_id`를 파라미터로 받고 EXECUTE 권한은 `service_role`에만 준다 |
| 소프트 삭제 | 조회, 수정, 집계 전부 `deleted_at IS NULL` 일관 적용 |
| 계정 삭제 | `app/api/account/delete/route.ts`의 `USER_SOFT_DELETE_TARGETS`에 `ballet_expenses`를 **반드시 추가** |
| 캐시 | `lib/balletNoteCache.ts` 모듈 스코프 캐시 + `sessionStorage` dirty flag. 무효화는 **맵 전체 비우기**로 (전역 boolean 방식은 다른 달이 stale로 남는다) |
| 날짜 선택 | `components/sheets/DatePickerSheet.tsx` 재사용. 월을 바꿀 때 일을 말일로 줄이는 보정이 이미 들어 있다 |
| 월 전환 스와이프 | 임계값 40px, 전환 직후 240ms 잠금 (없으면 두세 칸씩 건너뛴다) |
| 금액 입력 | 문자열로 받아 숫자 변환 시 `NaN`과 음수를 막는다. 서버에서도 검증한다 |
| 예외 처리 | 스토리지, 파싱, 네트워크 접근은 전부 try/catch + 안전측 폴백 |

## 6. MVP 범위

| 포함 (v1) | 제외 (v2 이후) |
|---|---|
| 지출 CRUD | 그래프와 차트 |
| 월 캘린더형 홈 + 그 달 총지출 | 예산 설정과 초과 알림 |
| 월 / 년 전환 + 총지출 + 태그별 리스트 | 레슨, 공연, 브랜드 지출 자동 취합 |
| 프로필 요약 카드 | 탭바 승격 |
| 태그 자동완성 | 다중 태그 |
| 어드민 목록과 상세 | CSV 내보내기, 통화 선택 |
